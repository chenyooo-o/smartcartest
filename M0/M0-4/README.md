## 参数说明

程序通过命令行参数接收用户指令。程序内部使用了 `argparse` 模块进行解析，并对异常输入进行了严格的拦截处理。

| 参数 | 数据类型 | 必填 | 默认值 | 详细说明与行为逻辑 |
| :--- | :--- | :---: | :---: | :--- |
| `--config` | String (路径) | **是** | 无 | 指定任务配置文件的路径。<br>• **支持格式**：`.yaml`, `.yml`, `.json`。<br>• **异常拦截**：若文件不存在、JSON/YAML 语法错误、任务列表为空、成功率越界、存在依赖环或依赖不存在的任务，程序将输出**易读的错误提示**并直接以非 0 状态码退出（绝不抛出系统堆栈）。 |
| `--timeout` | Float (浮点数) | 否 | 配置文件中的 `timeout` 值 | 全局任务执行的超时时间（单位：秒）。<br>• **优先级**：若命令行传入了此参数，将**强制覆盖**配置文件中的 `timeout` 值。<br>• **触发行为**：在执行前或 `sleep` 后检测到累计耗时 ≥ 超时时间，将立即中断调度，当前及后续未执行任务的状态都会被标记为 `TIMEOUT`。 |
| `--report` | String (路径) | 否 | `report.json` | 运行结束后生成的报告文件保存路径。<br>• **结构保证**：无论任务是否被跳过或超时未执行，该文件中 `tasks` 数组必定包含配置文件中的所有任务，且包含完整的执行状态、尝试次数和耗时。 |
| `--seed` | Integer (整数) | 否 | 无 (完全随机) | 随机数种子。<br>• **核心作用**：在每次运行前调用 `random.seed()`，使得相同配置在多次运行时的成功/失败判定结果**完全一致**。<br>• **使用场景**：极大方便了本地调试、复现 Bug 以及考官现场验收时的结果核对。 |

### 💡 参数优先级与交互说明

1. **超时覆盖机制**：程序确定超时时间的优先级为：**命令行 `--timeout` 参数** > **配置文件中的 `timeout` 字段** > **默认无限大**。
2. **目录安全**：若 `--report` 指定的路径所在目录不存在，程序会捕获写入异常并输出友好的错误提示，不会直接崩溃。


## 运行示例
1. python TaskScheduler.py --config tasks_demo.yaml --seed 42
2. python TaskScheduler.py --config tasks_demo.yaml --timeout 5 --seed 42
3. python TaskScheduler.py --config tasks_demo.json --report my_report.json --seed 100
