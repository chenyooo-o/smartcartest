# M1-4 系统调优

## 1. 项目简介

本项目基于 ROS 2 Humble，实现相机图像采集、图像处理和控制指令发布，并通过性能测试与故障定位，对系统进行调优。

主要目标：

- 相机图像输入频率达到约 30 Hz。
- 图像处理输出频率达到约 30 Hz。
- 控制指令发布频率达到 20 Hz。
- 图像处理端到端 P95 延迟小于 200 ms。

## 2. 文件结构

| 文件或目录 | 功能 |
|---|---|
| `camera_pub.py` | 模拟相机，发布图像数据 |
| `image_proc.py` | 图像处理及控制指令发布 |
| `crash_worker.py` | 节点故障测试程序 |
| `baseline.txt` | 优化前性能测试记录 |
| `FAULTS.md` | 故障现象、定位、根因、修复和验证记录 |
| `measurements/` | 性能测试脚本及测量数据 |
| `backup/` | 原始程序备份 |

## 3. 节点与话题

| 节点 | 功能 |
|---|---|
| `camera_sim` | 模拟相机，发布图像 |
| `image_proc` | 接收图像并进行处理 |
| `control_loop` | 定时发布控制指令 |

主要话题：

| 话题 | 消息类型 | 功能 |
|---|---|---|
| `/camera/image_raw` | `sensor_msgs/msg/Image` | 相机原始图像 |
| `/perception/result` | `sensor_msgs/msg/Image` | 图像处理结果 |
| `/control/cmd` | `geometry_msgs/msg/Twist` | 控制指令 |

## 4. 图像处理流程

图像处理节点接收相机发布的图像，执行以下操作：

1. 将输入图像转换为灰度图。
2. 对图像亮度增加 20。
3. 使用公式 `((v - 128) * 3 / 2 + 128)` 增强对比度。
4. 将像素值限制在 0～255。
5. 将处理结果以 `mono8` 格式发布到 `/perception/result`。

输出图像保留输入图像的时间戳和 frame_id。

## 5. 运行方法

打开终端，进入项目目录：

```bash
cd ~/smartcartest/M1/M1-4
source /opt/ros/humble/setup.bash
```

启动相机节点：

```bash
python3 camera_pub.py
```

另开一个终端，启动图像处理与控制节点：

```bash
cd ~/smartcartest/M1/M1-4
source /opt/ros/humble/setup.bash
python3 image_proc.py
```

## 6. 性能测试

优化前的实测数据：

| 指标 | 优化前 |
|---|---:|
| 相机输入频率 | 约 11.9 Hz |
| 图像输出频率 | 约 2.21 Hz |
| 控制输出频率 | 约 2.25 Hz |
| 平均端到端延迟 | 约 3.07 s |

本轮稳定状态下的实测数据：

| 指标 | 优化后实测 |
|---|---:|
| 相机输入频率 | 约 29.97～30.05 Hz |
| 图像输入、输出频率 | 约 27～30 Hz |
| P95 测量期间图像处理频率 | 约 29.01～30.34 Hz |
| P95 延迟 | 23.446 ms |
| 平均延迟 | 18.257 ms |
| 最大延迟 | 61.204 ms |

P95 测量成功采集 600 帧，未出现负延迟样本。P95 为 23.446 ms，小于 200 ms 的目标上限。

正式测量文件：

- `measurements/p95_samples_20261122.csv`
- `measurements/p95_test_output_20261122.log`

## 7. 性能权衡

系统调优需要兼顾处理速度、图像质量和资源占用：

- 提高图像处理效率，有助于提升输出频率。
- 控制消息队列深度可以减少积压，但队列过小可能导致旧帧被丢弃。
- 丢弃过期图像有利于降低延迟，但可能减少处理帧数。
- 图像分辨率越高，处理所需的计算资源通常越多。

本项目在保持 640×480 图像尺寸和约 30 Hz 相机发布目标的前提下进行调优。

## 8. 故障记录

测试过程中出现过相机话题接收频率异常偏低、图像处理频率下降、消息队列积压以及节点非预期消失等问题。

相关现象、定位过程、根因、修复措施和验证结果记录在 `FAULTS.md` 中。

其中，相机话题接收频率异常偏低的问题在重新启动节点后恢复，但最初根因尚未确定，因此不将重启描述为根因修复。

## 9. 项目结论

本项目完成了 ROS 2 相机图像采集、图像处理和控制指令发布链路，记录了优化前后的性能数据，并完成了 600 帧 P95 延迟测试。

本轮测得 P95 延迟为 23.446 ms，达到小于 200 ms 的验收目标。
